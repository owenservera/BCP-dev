## What could still make this model wrong?

- A runtime registration path may exist outside the inspected plugin/contract surfaces.
- A host composition mechanism may provide resource semantics not visible in provider-browser itself.
- Legacy engine inventory proves presence, not quality or current user value.
- Destination documents may intentionally leave some boundaries open rather than missing.
- Live external behavior remains under-proven.

## Strong falsifiers

1. Demonstrate a current Ω canonical Account object with selection, persistence and session binding.
2. Demonstrate two concurrent accounts and prove target isolation.
3. Restart Chrome/process and recover the same intended session/account without ambiguity.
4. Add a third provider without changing semantic capability contracts.
5. Add a new durable object kind and carry it through world, surface, export and restore.
6. Restart during background Work and recover an inspectable continuation state.
7. Change canonical evidence and prove self-knowledge freshness changes accordingly.
