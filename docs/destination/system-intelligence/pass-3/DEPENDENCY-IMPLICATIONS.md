# Pass 3 — Dependency Implications

> Classification: DERIVED — DEPENDENCY CONVERGENCE
> Status: current dependency interpretation from Pass 2 + Pass 3 characterization.

## 1. High-leverage dependency chain

```
Vault / Evidence
      ↓
Canonical Object / Relationship
      ↓
World Projection
      ↓
Account / Session / Resource
      ↓
Routing
      ↓
Durable Work
      ↓
Provider Knowledge
      ↓
Continuity / Self-Knowledge
      ↓
Product Surface
```

This is not a strict single build chain; several branches can proceed in parallel after their semantic contracts are fixed.

## 2. Dependencies by critical system

| System | Depends on | Blocks |
|---|---|---|
| Account | Provider + identity evidence + destination world | Routing, live provider work |
| Session | Account + realization + resource contract | external effect |
| Browser Resource | profile/process/target reality | live provider isolation/recovery |
| Routing | valid realizations + account model + user policy | predictable provider choice |
| Canonical Object | identity + revision + relationship model | World/Surface/Work/export |
| Durable Work | Object + Evidence + Intent/Plan integration | background continuity |
| Provider Knowledge | discovery + observations + realization + parser evidence | multi-provider evolution |
| Self-Knowledge | canonical source revision model + derivation basis | trustworthy introspection |
| Plugin reprogramming | contract boundaries + Recipe/authority | safe evolution |
| Product Instance | durable object/vault + composition/recovery | usable VIVIM shell |

## 3. Dependency implications

### D-I1 — Account before routing

Routing without account identity can produce a correct provider choice but wrong authenticated relationship.

**Status: EVIDENCE-SUPPORTED.**

### D-I2 — Browser experiment before broad session implementation

The browser seam is the highest external-reality uncertainty.

**Status: EXPERIMENT-REQUIRED.**

### D-I3 — Object envelope before broad canvas/work integration

Otherwise surfaces will create ad hoc persistence contracts.

**Status: DESIGN-CANDIDATE.**

### D-I4 — Work before background product claims

Background execution without durable outcome identity cannot provide trustworthy continuity.

**Status: EVIDENCE-SUPPORTED.**

### D-I5 — Provider KnowledgeView before autonomous healing promotion

Healing needs a queryable current knowledge context and evidence basis.

**Status: DESIGN-CANDIDATE.**

### D-I6 — Freshness before self-evolving claims

Without basis-aware freshness, self-knowledge can be stale while appearing authoritative.

**Status: DESIGN-CANDIDATE.**
