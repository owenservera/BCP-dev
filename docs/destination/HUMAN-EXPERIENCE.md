# VIVIM Human Experience

> Classification: DERIVED — WORKING / DRAFT

## The first minute
The person opens VIVIM and finds an already-existing world: projects, conversations, email, files, accounts, interests, tasks, memories, and recent history that VIVIM has been allowed to access.

When the person is actively working on a project, VIVIM can present that project as a live context: current state, relevant conversations, communication, decisions, open questions, and what appears to come next.

The first minute depends on why the person opened VIVIM. Continuing a project, researching, communicating, finding something, creating, and delegating work are all normal entry modes.

## A persistent world
VIVIM is a living representation of the person's digital world rather than a set of isolated applications.

Things such as projects, conversations, documents, people, accounts, repositories, services, agents, tasks, workflows, and ideas can exist in one environment while retaining their source identity and provenance.

The environment continuously organizes what is already there. The person should not have to manually build the knowledge structure for ordinary use.

## Intelligent infinite space
The primary visual language is an intelligent infinite spatial environment, potentially including depth and 3D relationships.

It can be compartmentalized into workspaces, projects, research areas, conversations, and application-like areas.

A space is not merely a folder. It is a context where things can be arranged, related, surfaced, and interacted with.

A thing can have different useful surfaces: tile, dashboard, graph, conversation view, project view, or application-like view.

## Direct manipulation
The person can work without speaking: navigate, focus, move, group, connect, open, inspect, resize, reorganize, create, and reconfigure.

The visual arrangement is a representation of the world, not the sole source of truth.

## The universal prompt
The prompt is a persistent native control surface.

The person can use it to address VIVIM, the current context, a particular thing, an agent, a plugin capability, another person, an external AI provider, a workspace, or a surface.

The prompt therefore serves as a command and configuration surface as well as a conversational surface.

## Address matters
The person is not simply "chatting." They are addressing something.

Context can make the target obvious, while explicit addressing can remove ambiguity when needed.

A request can therefore be directed to VIVIM, a project, an agent, an email conversation, Claude, ChatGPT, or another target without forcing the person to leave the environment.

## Creating
An idea can enter the persistent world immediately.

VIVIM can connect it to existing context, discover related material, help research it, and help turn it into a project, work item, memory, or composition.

The second-brain experience is therefore connected to the person's real digital activity instead of being a detached note system.

## Attention and proactivity
The person can configure what matters to them and what VIVIM should watch.

Standing attention can produce reports, alerts, notifications, research, and background work.

Proactivity should arise from configured interests and standing intent, not from unexplained product behavior.

## Delegation
Delegating work should feel like talking to an AI agent.

Example:
"Send an update on Project X to John covering where we are and what's next."

The agent may gather local information deterministically, assemble context, use the person's AI accounts for reasoning or generation, interact with external providers, and report the result.

The user sees the requested outcome, the progress, and the result rather than the orchestration machinery.

## Background continuity
Work can continue while the person is away.

Some work can be deterministic. Some may use the user's authenticated AI web sessions. The environment can tolerate slower web-app interactions by allowing durable background work rather than pretending every action must be instantaneous.

On return, the person should experience continuity:
what changed, what happened, what VIVIM did, what it found, what needs attention, and what comes next.

## Agency
The person decides what may happen automatically, what requires approval, and what is not delegable.

Those boundaries are part of ordinary environment configuration rather than an expert-only control panel.

## Core interaction loop
A current candidate loop is:

See → Focus → Understand → Address → Express intent → Decide/delegate → Act → Verify → Remember → Evolve

Not every interaction needs every stage. The loop is a design test for the environment.

## Design target
VIVIM should feel less like an application and more like a personal digital environment with an exceptionally capable interaction layer.

The person should feel that their machine, internet, accounts, apps, data, intelligence, rules, and interaction finally belong together in one coherent environment.
