# Investigator Protocol

## Phase 1 — Product + architecture bootstrap

Read destination authority and latest System Intelligence outputs.

Do not repeat broad archaeology already completed.

## Phase 2 — Legacy extraction

Build the Legacy harvest map.

Trace concrete code, schema, tests and behavior.

## Phase 3 — Modern comparison

Study current primary documentation and representative implementations.

Normalize unlike systems into primitive categories rather than framework terminology.

## Phase 4 — Semantic decomposition

For every candidate primitive ask:

- What problem does it solve?
- Is it durable?
- Does it need identity?
- Is it canonical?
- Is it authority-bearing?
- Does it survive restart?
- Does it need external reality?
- Can it be deterministic?
- Can it be represented in World + Work + Evidence?
- Can an existing Ω primitive already express it?

## Phase 5 — Falsification

Construct failure scenarios:

- process crash;
- repeated delivery;
- duplicate execution;
- stuck Work;
- missing resource;
- expired wait;
- revoked approval;
- changed Plan;
- conflicting trigger;
- concurrent Work;
- lost worker;
- partial effect;
- corrupted checkpoint.

## Phase 6 — Minimum substrate

Reduce the design until removing a primitive clearly breaks a required product journey.

## Phase 7 — Build handoff

Separate:

- can implement now;
- needs local experiment;
- needs future browser/provider experiment;
- needs product decision;
- needs Ω core change.

## Evidence discipline

Every substantive finding needs a source path/URL, location, date/version where available, and evidence kind.

Do not turn framework documentation into VIVIM authority.

Do not silently upgrade a Legacy implementation into destination truth.
