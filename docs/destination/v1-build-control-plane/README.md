DESIGN → EXPERIMENT → PROOF → IMPLEMENT → INTEGRATE → PRESSURE → NEXT SLICE

## Core idea
Do not build isolated subsystems. Build a real VIVIM spine repeatedly:

Intent → Capability → Routing/Choice → Authority → Work → Realization → External/Internal Effect → Result → Evidence → Durable World → Surface/Continuity

The most important first seam is:

Provider → Account → Session → Browser Resource → Realization

The next product seam is:

Work → Evidence → Canonical Object/Relationship → World → Surface → Continuity

## Working law
1. A design candidate is not authority.
2. An experiment may falsify a design.
3. Implementation does not prove semantics.
4. Live proof is distinct from fixture proof.
5. A surface never becomes canonical merely by existing.
6. Learned routing never becomes authority.
7. Forge proposals never become promotion automatically.
8. Temporary implementation is acceptable; invisible temporary architecture is not.
9. Legacy is behavioral evidence, never destination architecture.
10. Each completed slice must make the next dependency clearer.

## Exit criterion
The control plane succeeds when it can continuously answer:

What are we building now? Why now? What must be learned first? What proves it? What product journey does it unlock? What did it falsify? What changed next?
