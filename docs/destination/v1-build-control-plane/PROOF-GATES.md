# V1 Proof Gates

> A gate is evidence required for promotion, not a statement of intent.

| Gate | What it proves | Minimum evidence | Unblocks |
|---|---|---|---|
| G0 | Ω foundation preserved | gate/tests + no law violation | bridge work |
| G1 | one external identity chain | E1 live evidence | D1 implementation |
| G2 | account isolation | E2 evidence | multi-account |
| G3 | resource concurrency | E3 evidence | concurrent Work |

| G5 | generic object traversal | E6 evidence | world/surface integration |
| G6 | durable Work continuity | E7 evidence | background product claims |
| G7 | self-knowledge honesty | E8 evidence | freshness-backed introspection |
| G8 | provider generality | E5 evidence | broader provider abstraction |
| G9 | product continuity | S10 restart proof | V1 product-instance claim |

## Proof vocabulary
- FIXTURE-PROVEN
- LOCAL-PROVEN
- LIVE-PROVEN
- RESTART-PROVEN
- MULTI-RESOURCE-PROVEN
- PROMOTION-CANDIDATE
- PROVEN

Never collapse fixture proof into live proof.

## Gate discipline
A slice may continue before its next gate only when it is clearly partitioned from the unproved assumption.

A green unit test cannot turn an UNRUN live experiment green.

A gate failure must produce a narrowed design, explicit rejection, new experiment, or new implementation constraint. It must not be hidden as a workaround.
