## Harvest rule
behavior → product need → semantic requirement → destination contract → implementation candidate → proof

## Preserve as behavior
- provider/account/session relationships;
- account isolation;
- conversation/message/stream continuity;
- workspaces/canvas/project organization;
- background state and recovery;
- provider discovery/healing evidence patterns;
- backup/export/recovery behavior.

## Rebuild under Ω
- Account;
- Session;
- Browser Resource;
- Routing;
- Work;
- canonical objects/relationships;
- ProviderKnowledgeView;
- freshness;
- Product Instance lifecycle.

## Do not carry forward automatically
- anti-detection/stealth stack;
- historical telemetry architecture;
- tunnel/P2P machinery;
- monolithic engine hierarchy;
- old admin/config UX;
- provider-specific architecture as a universal model.

## Harvest record
HARVEST-ID / source-path / commit / observed behavior / why product needs it / destination concept / reuse candidate / conflicts / proof / disposition

Temporary implementation is acceptable. Invisible architectural coupling is not.
