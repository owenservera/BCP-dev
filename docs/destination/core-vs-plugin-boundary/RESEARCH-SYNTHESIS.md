# Research Synthesis

This pass reconciles current Ω invariants and decision records, Forge backlog, destination Core-vs-Plugin distillation, Everything-is-a-Plugin/Evolution constitution, dependency scorecard, product vision, current context and historical boundary work. Ratified Ω law remains authoritative; this package is derived.

K0 owns admission, integrity, isolation, transport, egress enforcement, generic lifecycle and minimal platform/crypto primitives. K1 owns shared protocol vocabulary. System plugins own bundled product capabilities, policy content, domain data and realizations. Extension plugins use the same governed surface. Tooling remains outside runtime authority.

The strongest K0 candidates are signed Recipe/manifest admission; content/signature verification; plugin compartment and Port transport; host-side capability-token verification, revocation and fencing; atomic activation/recovery; a minimal OS seam; cryptographic/canonical identity primitives; and generic runtime lifecycle.

This aligns with Ω B1–B5: admission, isolation/transport, host-side capability enforcement, fail-closed recovery and the hard host-minimality boundary. The current law also states that everything else is a plugin and the host is transport, not policy.

False-Core rule: essential, ubiquitous, security-sensitive, bundled or frequently called is not sufficient for K0. The decisive question is whether moving the responsibility to a plugin creates an unsafe bypass of the boundary that must protect all plugins.

Mixed-boundary examples: capability = K1 reference + plugin definition + K0 egress enforcement; law = K1 decision contract + plugin policy content + K0 enforcement; evidence = K1 reference/envelope + plugin store + K0 integrity primitives; Work = K1 reference/lifecycle + plugin semantics; Object = K1 identity/revision + plugin-owned meaning/storage; resource control = K0 hard safety bounds + plugin policy/economics.

A normal VIVIM installation is a signed composition of system plugins. Replacement is propose → impact → compatibility → authority → atomic activation → verify → monitor → rollback/quarantine. Active Work retains a stable semantic reference and explicit implementation compatibility state.

Zero-plugin boot can expose diagnostics, admission and installation primitives without pretending to provide the VIVIM product experience. This is intentional: product semantics stay out of K0.

Decision: make Core harder to grow than plugins. Every K0 proposal must name the bypass it prevents, universal mechanism, domain-neutrality argument, removal candidate and falsifier.
