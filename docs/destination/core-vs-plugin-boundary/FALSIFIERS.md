# Falsifiers

F1: A concrete plugin can bypass a supposedly K0 safety rule. If yes, the K0 boundary is too weak or wrongly placed.

F2: A proposed K0 responsibility can be removed and implemented as a plugin without weakening universal safety. If yes, it is false Core.

F3: A first-party system plugin requires a private runtime path unavailable to legitimate extensions without a proven trust-tier reason. If yes, symmetry is incomplete.

F4: Replacing a system plugin destroys canonical user history despite a compatible contract. If yes, the replacement seam is inadequate.

F5: Active Work cannot survive implementation replacement or explicit migration. If yes, Work continuity is under-specified.

F6: Zero-plugin boot cannot admit, inspect or install a valid composition using K0 plus contracts. If yes, hidden product semantics remain in Core.

F7: A contract change silently changes canonical semantics without impact/compatibility evidence. If yes, evolution controls are insufficient.

F8: Provider healing can silently promote a generated realization into authority. If yes, evolution admission is unsafe.

F9: Dependency impact requires domain-specific hard-coded knowledge in Core. If yes, graph contracts are insufficient; do not immediately enlarge Core—first test a richer K1 metadata model.
