# CONFLICT: close-out directive status IN_PROGRESS vs STATE vocabulary

> **Classification: DERIVED — CURRENT**

```yaml
id: INS-20260924-220000
date: 20260924
author: IMPL-04
mission: AMP-1
kind: FINDING
status: ADOPTED
confidence: high
sources: close-out directive section 2.3; agent-tools/agent_lint.py STATE_STATUSES; missions/amp-1/STATE.md
```

## Claim

Close-out §2.3 orders STATE status "back to IN_PROGRESS", but the STATE
status vocabulary (enforced by lint) has no IN_PROGRESS — only
DRAFT|ACTIVE|DONE|BLOCKED|PAUSED|ABANDONED. Safer reading applied:
status ACTIVE (mission active again), since IN_PROGRESS names a body
section, not a status.

## Why

Weakening the gate (adding IN_PROGRESS to the vocabulary) to satisfy the
directive's letter is explicitly forbidden by close-out §5. The
vocabulary is the standing rule; the directive's intent (reopen the
mission) is fully served by ACTIVE.

## Alternatives considered or rejected

- Add IN_PROGRESS to STATE_STATUSES: rejected, gate-weakening.
- Leave status DONE during close-out: rejected, DONE means complete and
  would misrepresent verification work still running.

## Consequences

In force: close-out runs under ACTIVE; future directives should order
ACTIVE, not IN_PROGRESS. Lint refusal demonstrated live (it also caught
a `clean tree` phrasing in the fixture STATE during the same run).

## Evidence

Live lint output: `REFUSED: .../amp-1/STATE.md has invalid status
'IN_PROGRESS'` (twice — pre-commit and commit-msg halves).
