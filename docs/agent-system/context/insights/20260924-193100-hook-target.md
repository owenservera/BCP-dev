## Claim

`ops-install.ps1` installs the BCP validate gate to
`$PSScriptRoot/.git/hooks/pre-commit`, i.e. `bcp-speed/bcp/.git/hooks`,
but the operative repository root is `BCP-dev/` (mission branches live
there). The AMP-1 L1 gate therefore lives versioned at
`agent-tools/hooks/` with `core.hooksPath` pointed at it, and chains the
BCP validate behavior instead of replacing it.

## Why

MY-LOOP.md speaks of committing "in `bcp/.git`", yet mission work
(`mission/amp-1`) happens in the BCP-dev root repo. Installing the L1
rules into the root repo's hook path is the only placement that actually
gates mission commits. Chaining (BCP validate first, then L1) keeps the
state-validation refusal intact; this is verified by test, not assumed.

## Alternatives considered or rejected

- Overwrite `.git/hooks/pre-commit` directly: rejected, unversioned and
  invisible to review; `core.hooksPath` to a versioned dir is reviewable.
- Replace BCP validate with L1 only: rejected, would drop the
  corrupt-state refusal the forge depends on.
- Treat MY-LOOP's `bcp/.git` as authoritative and gate there: rejected,
  mission branches do not live there.

## Consequences

In force for the mission: `agent-tools/hooks/pre-commit` runs
`python bcp-speed/bcp/validate.py` semantics first, then
`agent_lint.py --pre-commit`; `commit-msg` enforces STATE-touch/trailer
and Decision-trailer rules. `AMP_HOOK_BYPASS` is the only bypass and is
logged. ops-install.ps1 itself is untouched except the additive hourly
WIP line (commented, owner enables).

## Evidence

Hook sources read 2026-09-24; L1 refusal paths unit-tested; BCP validate
still reports 0 errors (self-test phase re-verifies end to end).
