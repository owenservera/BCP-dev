# WS-010 — V0 Proof Plan

> **Classification: DERIVED — PROPOSED V0**

## Proof thesis

The Program Observatory is useful and trustworthy only if it provides a
human-readable visual reflection of program state while preserving source
authority, uncertainty and provenance.

## Proof dimensions

### P-01 — Human comprehension
A fresh user can understand a representative entity without knowing its internal ID.

### P-02 — Source traceability
Every material displayed state has a traceable source/evidence route.

### P-03 — Authority preservation
The observatory never outranks an existing source authority.

### P-04 — Unknown preservation
Unknown and unresolved state survives projection.

### P-05 — Relationship correctness
Displayed relationships correspond to explicit or mechanically justified sources.

### P-06 — State correctness
Visual state corresponds to source-derived state dimensions and remains
understandable without color.

### P-07 — Semantic zoom
Zoom increases contextual detail without changing the underlying entity.

### P-08 — Read-only integrity
Navigation, filtering, zooming and view switching cannot mutate project authority.

### P-09 — Multi-view consistency
Different views are projections of one model.

### P-10 — Rebuildability
Derived observatory state can be rebuilt from source systems.

### P-11 — Attention discipline
Attention reflects recorded/derived conditions but does not invent priorities.

### P-12 — Boundary discipline
The observatory does not duplicate P1-02, P1-03, P1-04, P1-05, P1-06 or P1-09.

## Minimum adversarial suite

1. P1-02 displayed by ID only.
2. Historical document looks newer by filesystem time.
3. Branch is ahead of main but not merged.
4. Generated artifact disagrees with its source.
5. Similar files are semantically distinct.
6. Genuine duplicates exist.
7. Sources conflict with no governing authority.
8. Owner is absent.
9. Untracked local surface exists.
10. Agent report contradicts repository state.
11. Attention condition has no authoritative priority.
12. A view tries to mutate state.
13. Cache is deleted and rebuilt.
14. Color is unavailable.
15. Relationship exists only because nodes are adjacent.

## Definition of V0 proof

Do not call V0 PROVEN until the proof dimensions have explicit evidence and the
owner/coordinator has accepted the resulting proof package.

A polished UI without these proofs is a prototype, not a proven observatory.
