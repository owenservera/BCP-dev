## NON-NEGOTIABLE INVARIANTS

### 1. Observation ≠ Interpretation
```typescript
// VALID
{ kind: "git.branch.ahead", value: 3 }
{ kind: "process.exit_code", value: 0 }

// FORBIDDEN
{ kind: "branch.safe_to_merge", value: true }
{ kind: "task.succeeded", value: true }
```

### 2. CURRENT Is Earned
A snapshot may claim CURRENT only when:
- Required basis freshly observed within freshness window, OR
- Valid freshness proof exists (basis digest match)
- NEVER because "we cached it 5 minutes ago"

### 3. Unknown Is Valid
Comfortably return:
- UNKNOWN (not yet observed)
- UNOBSERVABLE (cannot observe with available tools)
- STALE (basis changed since observation)
- UNRESOLVABLE (attempted, could not determine)
- CONFLICTED (contradictory observations exist)

### 4. Execution Success ≠ Semantic Success
```typescript
type ExecutionAxis = "EXIT_0" | "EXIT_NONZERO" | "TIMEOUT" | "KILLED";
type ResultAxis = "RESULT_PRESENT" | "RESULT_EMPTY" | "RESULT_MALFORMED";

// EXIT_0 + RESULT_EMPTY is NOT "success"
// No layer may collapse these into generic SUCCESS
```

### 5. Branch State ≠ Mainline State
A commit on feature branch ≠ commit reachable from current main.
All three (onCurrentBranch, onLocalMain, onRemoteMain) can differ.

### 6. Reported Fact ≠ Durable Fact
Agent output is an observation about what agent CLAIMS happened.
You must reconcile against machine state.

### 7. Never Silently Repair Semantic State
You may mechanically regenerate stale caches.
You must NOT rewrite: architectural meaning, CFA ownership, authority decisions, Ω law, task intent, canonical identity.

### 8. No Second Authority System
If Git says X and cached snapshot says Y:
- Git remains authoritative for Git state
- You report CONFLICTED
- You do NOT become authoritative over Git

### 9. Speed Lives Inside Envelopes
Speed comes from fast observation, not from skipping verification.
Make observation so cheap that verification gates never become bottlenecks.

### Git Observer (reality-git)
**Commands:**
```bash
git rev-parse --show-toplevel
git branch --show-current
git rev-parse HEAD
git rev-parse refs/heads/main
git rev-parse refs/remotes/origin/main
git merge-base HEAD origin/main
git rev-list --left-right --count HEAD...origin/main
git status --porcelain=v2 -z
git remote -v
git --version
```
**Rules:**
- Use `--porcelain=v2` and `-z` for machine output
- Treat origin/main, local main, current branch as SEPARATE identities
- Never reimplement Git graph logic

### Filesystem Observer (reality-fs)
**Tiered strategy:**
- Level A: metadata (path, size, mtime, type) — every cycle
- Level B: content digest (SHA-256) — on mtime/size change or explicit request
- Level C: full content — explicit expensive operation only

**Flow:** watcher event → mark dirty → metadata re-read → optional digest
**Never treat watcher event as final state.**

### Process Observer (reality-process)
**Identity:** PID + startTime as generation token (PID alone insufficient)
**Classification patterns:**
```typescript
[
  { pattern: /opencode.*--agent/i, classification: "opencode-agent" },
  { pattern: /opencode.*worker/i, classification: "opencode-worker" },
  { pattern: /bun(\.exe)?\s/i, classification: "bun-runtime" },
  { pattern: /node(\.exe)?\s/i, classification: "node-runtime" },
  { pattern: /tsc(\.exe)?\s/i, classification: "typescript-compiler" },
  { pattern: /vitest|jest|mocha/i, classification: "test-runner" },
]
```

### OpenCode Observer (reality-opencode)
**Critical: phantom worker detection**

### Toolchain Observer (reality-toolchain)
**Probes:** bun, node, npm, pnpm, typescript, git, powershell, opencode, python

### Verification Observer (reality-verify)

## DEGRADATION STATE MACHINE

```
HEALTHY → observer error → DEGRADED
DEGRADED → multiple failures → CRITICAL
CRITICAL → storage failure → FAILED
```

**Per-observer degradation:**
- Git commands fail → use last good, mark STALE
- Watcher fails → poll-only mode
- Process query fails → last good list, mark STALE
- OpenCode unavailable → process-only observation
- Tool not found → report available, mark missing UNAVAILABLE
- Execution impaired → queue commands, report NOT_RUN

**NEVER substitute stale cache silently.**

## DESIGN JUDGMENT

> **The most important design choice is to resist making Phase 1 "smart."**
>
> It should be boringly factual. A highly reliable factual substrate will later make sophisticated intelligence much safer and much faster. An intelligent but unreliable reality layer would multiply false context, stale reasoning, and agent rework.
>
> Speed lives inside envelopes, never by skipping verification. Observation is so cheap that gates never become bottlenecks.

```

```
