### The Vivim System Vision: The Sovereign AI Substrate

Vivim is not a chat wrapper, nor a simple aggregator; it is architecturally defined as a **local-first AI conversation operating system**. It serves as a programmable substrate on which intelligent, composable, and privacy-preserving workflows execute entirely on the user’s machine (via a Tauri desktop shell and Bun runtime), requiring no central cloud account.

The philosophical core of the system is the concept of the **"Sovereign Mirror."** Vivim rejects the extractive, attention-harvesting models of hyperscalers, positioning itself as a tool for digital self-determination. It connects to external intelligence (ChatGPT, Claude, Gemini, DeepSeek, Qwen, Grok) while ensuring that the user retains absolute ownership of their data, memory, and execution environment.

---

### Core Concepts

The architecture is built upon several high-concept pillars that separate Vivim from standard AI applications:

*   **The Capability System:** This is the fundamental atom of the system. Every interaction—whether `send_message`, `select_model`, or `create_chat`—is defined as an atomic, typed operation called a **UnifiedCapability** (e.g., `cap:chat:send_message`). These capabilities are not hardcoded UI actions; they are abstract entities bound simultaneously to the CLI, API, UI, and MCP (Model Context Protocol).
*   **Atomic Cognitive Unit (ACU) & The Knowledge Graph:** Vivim models all domain objects (conversations, memories, agents) as **Nodes** within a graph. These nodes possess cryptographic provenance (`contentHash`), version chains, and weighted edges, forming a "cap-store" that natively captures the lineage and evolution of human-AI interactions.
*   **Natural Language Command Language (NLCL) & Reprogrammability:** The system is inherently mutable. It features a "closed mutation grammar" that allows users and agents to reshape the product’s interface and kernel behaviors at runtime using near-natural language. Every mutation is logged, versioned, and cryptographically verifiable.
*   **The Execution Kernel & Chrome Governor:** To interact with closed web-based providers, Vivim employs a specialized execution environment. The **Chrome Governor** manages the Chrome DevTools Protocol (CDP), acting as a secure, resilient bridge that "harvests" and "injects" data into provider interfaces when official APIs are unavailable or restrictive.
*   **Dual-DB Architecture:** A strict, forensic-level boundary exists between the **System Database** (configuration, provider seeds, capability registries) and the **User Database** (private conversations, semantic memory). This ensures that platform updates never compromise private user states.

---

### The Core Capability Vision

The vision for Vivim's capabilities is centered on **Unified Intent, Agentic Autonomy, and Surface Parity.**

1.  **Unified Intelligence & Resolution:**
    The user should never need to know *which* provider is handling a task or *how* the protocol works. The **Capability Resolution Engine** takes a natural language intent, translates it into a resolved capability with a confidence score, and routes it to the appropriate provider. Vivim includes specialized parsers for every major streaming format (SSE, `batchexecute`, reasoning deltas), making the underlying provider invisible to the user.

2.  **Agentic Autonomy (ActionPlan IR):**
    Vivim is designed to be an "Agentic Backbone." It utilizes an **ActionPlan Intermediate Representation (IR)** and a **Fleet Supervisor** to orchestrate multi-step, autonomous workflows. It can break down high-level goals, manage "slave" execution threads, handle circuit-breakers, and even "heal" broken selectors in browser automation without human intervention.

3.  **Surface Parity:**
    A defining capability of Vivim is that the "Surface" (where the user interacts) and the "Kernel" (where the logic lives) are perfectly synchronized. Any capability available to the AI agent is equally available to the user via the CLI or UI. This parity ensures that automation is transparent and controllable.

4.  **Self-Referential Knowledge (The Auto-Librarian):**
    The system is self-describing. Through a massive internal "Source Atlas" and "Librarian" engines, Vivim automatically generates and maintains its own documentation. It can answer "What am I?" and "Why was this decision made?" by querying its own architectural forensics, enabling a level of autonomous debugging and self-improvement rarely seen in desktop software.

In summary, Vivim’s vision is to provide a **hot-swappable, privacy-sovereign microkernel** where the user commands a fleet of AI capabilities through a unified, natural-language interface, all while maintaining a complete, cryptographic history of their digital thought process.
