# Intake and Reconciliation Protocol

## Trigger conditions

Run the Steward intake whenever:

- a workstream publishes research;
- a new design package lands;
- an implementation changes a canonical boundary;
- a new responsibility appears;
- an agent creates a substantial document outside canonical structure;
- a branch contains useful work that is about to be abandoned/merged;
- a dependency or maturity claim changes;
- a contradiction is discovered.

## Intake packet

Every intake begins with:

- source artifact/ref;
- producing workstream/agent if known;
- date;
- purpose;
- claimed status;
- subjects touched;
- explicit evidence;
- explicit decisions;
- open questions.

## Reconciliation procedure

### A. Identity

Is this new knowledge, a refinement, a duplicate, a contradiction, or historical material?

### B. Placement

Which canonical domain/system/responsibility owns the meaning?

### C. Decomposition

Does the artifact combine multiple responsibilities that should be separate?

### D. Depth

At what documentation depth does the useful information live?

### E. Dependency

Which canonical entities does it depend on or affect?

### F. Authority

Which existing authority governs each claim?

### G. Evidence

What source proves/supports/contradicts it?

### H. Freshness

Which current views are now stale?

### I. Promotion

What durable canonical views should be updated?

### J. Closure

What remains unmodeled, ambiguous, blocked or experiment-required?

## Reconciliation outcomes

Use explicit outcomes:

INCORPORATED
REFINEMENT
DUPLICATE
CONTRADICTION
HISTORICAL
UNKNOWN
PARTIAL
PROMOTION-CANDIDATE

Do not use “merged” to mean “understood.”

## Non-conforming artifact rule

The Steward does not require source documents to be rewritten into canonical prose.

The source remains source.

Canonical mapping is a second, structured layer.
