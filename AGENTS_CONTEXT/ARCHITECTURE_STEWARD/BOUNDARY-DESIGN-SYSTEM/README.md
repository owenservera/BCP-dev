# Boundary Design System v0

> Status: PROPOSED OPERATING SYSTEM FOR ARCHITECTURAL COORDINATION
> Owner: Architecture Steward
> Classification: DERIVED coordination protocol; not Ω law

## Purpose

Provide one small shared protocol for describing, comparing, challenging, and maintaining boundaries between Core Function Areas (CFAs).

This is **not** a universal ontology, canonical data model, authority system, or runtime subsystem.

## Ownership

- Architecture Steward owns this protocol, schemas, templates, register/index, reconciliation, and derived views.
- Each CFA owns the semantic claims about its own responsibility.
- A cross-CFA boundary is jointly authored by the participating CFAs and reconciled by the Steward.
- Human owner resolves unresolved product/constitutional questions.

## Source-of-truth rule

The Boundary Design System records architectural claims and their evidence. It does not become authority merely by being registered.

Treat:
- CFA responsibility claims as owned-domain assertions.
- Boundary records as reconciled coordination artifacts.
- Graph edges derived from boundary records as projections.
- Ω law, canonical domain semantics, implementation truth, and product policy as separately authoritative where applicable.

## Files

- `BOUNDARY-PROTOCOL.md` — operating rules and lifecycle.
- `SCHEMAS/` — machine-readable v0 structures.
- `ROUND-1-BOUNDARY-BOOTSTRAP.md` — the common prompt sent to every CFA.
- `ROUND-1-CFA-MATRIX.md` — the assignments and routing matrix.
- `MAINTENANCE.md` — review triggers and Steward duties.

## v0 principle

> Standardize the interfaces between agents' thinking before standardizing how they think internally.

The CFAs may retain their own research methods, conceptual models, tools, and terminology where those remain useful. The shared protocol standardizes only what must cross a responsibility seam.
