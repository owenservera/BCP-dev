## 1. Executive strategic synthesis

Across the ten independent roadmaps, the common strategic destination is **continuity across semantic, durable, governed, executable and experiential boundaries without collapsing ownership**.

The independently produced models converge on these system-wide invariants:

1. Meaning, evidence, representation, authority, execution, realization, composition, surface state and runtime enforcement remain distinct responsibilities.
2. Identity must survive representation and implementation change without becoming synonymous with a storage ID, provider ID, UI ID or plugin identity.
3. Unknown, ambiguous, stale, conflicted, refused and unavailable states must remain explicit rather than being normalized into success/failure shortcuts.
4. Consequential actions must travel through an attributable semantic → authority → realization/execution → runtime → evidence corridor.
5. Persistence must support reconstruction and continuity without becoming a hidden second authority or ontology.
6. Replaceability is a first-class requirement across providers, compositions, surfaces, Work and runtime components; replacement must preserve whatever semantics the change does not intentionally alter.
7. The first strategically useful proof is not a broad product slice. It is a set of small, cross-CFA seam contracts and falsifiable evidence packets that make later integration safe.

The roadmaps therefore support a **contract/evidence-first progression**:

`semantic kernel + continuity`
→ `cross-CFA seam contracts`
→ `governed executable corridor`
→ `live realization`
→ `replacement / evolution proof`
→ `product-grade multi-surface journey`.

This is a sequencing observation, not a new Ω law.

## 9. Proposed central sequencing

### Stage 0 — Cross-CFA contract and evidence closure

Advance the first bounded M1 evidence/contract work already queued in the ten CFA homes. The work is intentionally parallel within domain ownership.

Primary subjects:
- World semantic kernel and reference states;
- Data continuity identity/revision;
- Semantic continuity baseline;
- Authority corridor vocabulary;
- Work envelope;
- Capability→realization contract;
- Composition identity;
- Surface/View contract;
- Change contract;
- K0/B1 evidence closure.

**Boundary:** design, fixtures, traceability and falsification only. No production implementation is required to close Stage 0.

### Stage 1 — One end-to-end governed corridor

Select one narrow, already-supported consequential journey after Stage 0 evidence is compared. The corridor should cross:

semantic meaning → authority → Work/Attempt → capability/realization → runtime enforcement → evidence → surface projection.

The existing `message.send@1` / governed-action proof vehicle is a candidate, not a preselected mandate.

**Success condition:** the same effect can be followed across the seam contracts with attributable inputs, live authority, runtime enforcement, external realization, and reconstructable outcome/evidence.

### Stage 2 — Reconstruction, replacement and evolution

Exercise restart, replay, provider replacement, composition replacement and controlled evolution on the proved corridor.

**Success condition:** valid replacement preserves intended semantic/data/Work continuity; invalid or insufficiently evidenced changes stop, quarantine or refuse as appropriate.

### Stage 3 — Product-grade multi-surface journey

Use the proved semantic and execution corridor to validate Canvas/Workspace/Chat/future surfaces, direct manipulation, re-entry, evidence presentation and parity.

**Success condition:** different surfaces are projections over the same canonical subjects and work without hidden semantic duplication.

### Stage 4 — Broad provider/composition portability and self-maintenance

Only after the core corridor is stable should broad provider healing, heterogeneous portability, Forge expansion and stronger self-maintenance automation become shared execution programs.

**Success condition:** automation is evidence-bounded, replaceable and recoverable rather than merely clever.

## 11. Divergence preservation

The following local differences are intentionally retained:

- CFA-01 treats a bounded semantic World as primary and resists a universal ontology.
- CFA-02 treats continuity as the cross-boundary problem and resists making Data the semantic owner.
- CFA-03 treats semantic continuity as a traceability problem rather than a compiler-size problem.
- CFA-04 requires live authority semantics to remain distinct from historical evidence.
- CFA-05 treats Work as a durable execution subject, with truthful external outcomes remaining separate from local execution state.
- CFA-06 keeps routing/candidate selection distinct from Authority and treats live provider proof as an empirical step.
- CFA-07 makes Composition first-class without equating composition membership with permission.
- CFA-08 emphasizes projection/re-entry and direct manipulation without allowing surfaces to become semantic owners.
- CFA-09 keeps automation bounded by impact/reversibility/evidence rather than assuming self-maintenance is universally safe.
- CFA-10 insists K0 remain small and domain-neutral, with stronger containment deferred until the threat model justifies it.

These are complementary domain perspectives, not contradictions.
