## Ranking rule

Ranked by leverage under the CFA-09 operating loop:

`CHANGE SIGNAL → SUBJECT + SEMANTIC DELTA → IMPACT → COMPATIBILITY →
AUTHORITY IMPLICATIONS → BOUNDED APPLICATION → VERIFY → PROMOTE/QUARANTINE →
CONTINUITY → ROLLBACK/RECOVER/RETIRE`

A tool ranks higher when it (a) stops an unsafe change earlier, (b) preserves
history/lineage that can never be reconstructed after the fact, or (c) turns an
UNKNOWN (silent danger) into an explicit, routable condition. Generic
productivity value is out of scope for the ranking; every row must earn its
place through evolution/continuity leverage.

## Rationale (why this order)

1. **Gate before engine.** Tool 1 (validator) + tool 2 (lineage) stop bad change and preserve the history every later tool depends on. An impact analyzer without lineage is a faster way to lose the past.
2. **Vocabulary before verdicts.** Tools 3–4 fix the shared language (change unit, compat dimensions) before tools 5–7 render verdicts (impact, migration, replacement) in that language — the roadmap's own semantics → impact/compatibility → continuity/migration → replacement sequence.
3. **Refusal is evidence.** Tool 8 ranks above observability because an unproven envelope makes every "automatic repair" a covert privileged mutation; proving refusal first is what earns tools 9–10 the right to act.
4. **Substrate last enables, never governs.** Tool 10 is ranked tenth deliberately: full machine access multiplies the power of tools 1–9 but contributes zero governance. A team that installs the substrate without the gate gets faster drift, not autonomy.
5. **Reuse-first discipline.** Every ALREADY-EXISTS substrate (Ω vault, D-315/D-326 patterns, Forge proving, Provider Lab/Chrome master-slave per D-418, dependency graphs, Ω gates) is reused before anything new is proposed — the roadmap's "small extensions likely justified / not justified" list is honored row by row.
