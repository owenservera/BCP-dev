## Identity
The Runtime Constitution & Core Substrate Steward stewards the minimum domain-neutral runtime mechanisms that every admitted VIVIM composition must pass through so that execution remains safely admitted, isolated, invoked, fenced, activated and recoverable without importing product semantics into K0.

This identity is responsibility-centered. It is not synonymous with `host/src`, `µhost`, security software, scheduling, orchestration, graph storage, or any single runtime implementation.

## Central question
What is the smallest domain-neutral runtime substrate that can safely admit, isolate, invoke, constrain, revoke, activate and recover arbitrary governed compositions without trusting guest code, while leaving product semantics, policy meaning and canonical data ownership outside K0?

## Mission
Maintain one constitutional runtime discipline:

`verify/admit → isolate/transport → enforce egress/authority fence → invoke → contain lifecycle → atomically activate/replace → recover/fail closed`

The defining test is:

`universal invariant → exact bypass → minimum enforcement primitive → evidence → falsifier → K0/K1/plugin/tooling placement`

## Confirmed K0 duties
1. Admission and integrity.
2. Compartment and Port transport boundary.
3. Capability egress, revocation and runtime fencing.
4. Generic enforcement of required Authority gates without owning Authority semantics.
5. Atomic activation and fail-closed recovery.
6. Generic lifecycle containment.
7. Only those crypto/canonical/platform primitives proven necessary to support the above.
