## 2. New durable knowledge that was not previously explicit enough

### E-01 — CFA-01 is a semantic source/consumer, not a semantic hub

The strongest boundary lesson from the whole session is:

> CFA-01 should provide World meaning to neighboring systems and consume neighboring meanings at explicit seams; it should not become the central registry through which all of those systems are forced to operate.

This is stronger than simply saying “do not create another database.”

A request for a World registry, World graph, context store, object manager, visibility database, or world singleton should trigger a boundary test before any design work.

### E-02 — The primary failure mode is plausible false coherence

The most dangerous CFA-01 failure is not an obvious crash.

It is a clean-looking World model that quietly:
- treats an observation as a fact;
- treats evidence as the observed thing;
- treats correspondence as identity;
- treats a projection as current truth;
- treats retrieval relevance as authority;
- treats visibility as permission;
- treats Context selection as durable World state.

Therefore CFA-01 tooling should optimize for **semantic falsification**, not just navigation.

### E-03 — “World” needs an explicit scope model

The bootstrap treated World as a coherent user-owned reality, but the final audit exposed an unresolved architectural question:

> Is World total local knowledge, accessible local reality, or a principal-scoped projection?

This affects privacy, sharing, retrieval, agents, context and continuity. It deserves first-class investigation rather than being left as an implicit assumption.

### E-04 — Observation is a missing semantic layer

The bootstrap already distinguished:
- canonical object;
- evidence;
- memory;
- projection;
- authority.

It did not sufficiently distinguish:

`EXTERNAL OBSERVATION → WORLD ASSERTION/STATE → EVIDENCE → INFERENCE`

That chain should be treated as a first-class conceptual test.

### E-05 — External reconciliation is core World work

Provider/browser realization can observe or mutate the external world.

The World responsibility is not merely “represent the resulting object.” It must also characterize how:
- external change;
- missed observation;
- duplicate observation;
- stale state;
- conflicting observations;
- unknown external effect

become truthful local World state.

This is a central bridge between CFA-01, CFA-05, CFA-06, CFA-09 and evidence/provenance.

### E-06 — Context semantics must precede Context mechanics

D-443 is already a valuable deterministic mechanism.

The missing question is semantic:

> Why is this item relevant to this Context?

Therefore the correct progression is:

`WORLD + SPACE + FOCUS + WORK + INTENT + MEMORY + POLICY + FRESHNESS`
→ semantic relevance
→ D-443 assembly

not the reverse.

### E-07 — Identity is a temporal process, not just an identifier

The session repeatedly used identity layers correctly, but the deeper lesson is that CFA-01 needs to reason about **identity continuity across time**:
- merge;
- split;
- alias;
- source migration;
- retirement;
- re-identification;
- evolving correspondence.

Identity must be understood as a continuity problem as well as a naming problem.

### E-08 — The “one tool” should be a platform for modes, not a giant monolith

The Grounded Semantic Trace is the right central instrument because many CFA-01 questions share the same structure.

But it should remain a **trace framework with bounded modes and fixture packs**, not an all-powerful autonomous architecture service.

The preferred pattern is:

`ONE TRACE ENGINE + SMALL MODES + DETERMINISTIC FIXTURES`

rather than one new executable/tool per semantic gap.

### E-09 — Peer relationship distance is useful only as a coordination heuristic

The peer distance map successfully exposed proximity, handoff pressure and boundary risk.

But it must never be interpreted as:
- authority;
- priority;
- quality;
- maturity;
- peer consent.

The map is specifically a **CFA-01 perspective** and inferred peer needs require confirmation.

### E-10 — Bootstrap artifacts should optimize for future re-entry

The session exposed a useful success criterion:

> A fresh CFA-01 instance should be able to recover not only “what is my role?” but also “what did the previous bootstrap learn, what was deliberately left unresolved, which peers changed, which tools exist, and where should I start next?”

This implies the durable seed should remain reference-heavy and case-oriented.

## 3. Process lessons

### P-01 — Read peers before claiming a boundary

The peer constellation materially changed the interpretation of CFA-01.

The Architecture Steward is not merely a parent directory. It is the architectural reconciliation layer.

CFA-02 is not simply “database.”
CFA-03 is not simply “language.”
CFA-04 is not simply “law.”
The boundary only became useful after understanding the actual semantic question each peer carries.

### P-02 — Self-audit must be a deliberate bootstrap phase

The final adversarial pass uncovered important gaps that ordinary self-design did not surface.

Therefore a future Core Function Area bootstrap should include an explicit final question:

> “What would fail or become misleading if this seed stopped here?”

That question should happen before temporary closure.

### P-03 — The best artifact is often discovered after several smaller artifacts

The sequence of:
- seed;
- operational state;
- research queue;
- one-tool design;
- peer distance map;
- gap register

was more informative than trying to author a single master document.

This supports the Steward's existing anti-bloat rule.

### P-04 — Conversation itself is architectural evidence, but not authority

The owner-agent dialogue surfaced intent and boundary choices that repository documents could not fully determine.

That dialogue should therefore have durable lineage when it changes architecture.

However:

`CONVERSATION ≠ CANON`

A dialogue can explain why a boundary was chosen without becoming the authority that enforces it.
