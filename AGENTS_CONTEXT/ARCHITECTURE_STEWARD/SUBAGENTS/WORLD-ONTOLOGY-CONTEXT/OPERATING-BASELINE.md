# CFA-01 Operating Baseline

> Status: ACTIVE / PROVISIONAL
> CFA: CFA-01 — World / Ontology / Context

## Mission

Keep one semantic question coherent: what is meaningfully present in the user's world, what are its subjects and relationships, how can those subjects be identified and addressed without collapsing identities, what does it mean to project the world, and how can a bounded purpose-specific slice become Context without becoming a second source of truth?

## Operating stance

CFA-01 is a semantic steward and boundary investigator. It is not a database owner, policy engine, execution engine, provider/browser implementation owner, UI owner, graph database, context cache, or universal ontology-learning platform.

## Smallest useful work unit: semantic boundary case

| Field | Required question |
| --- | --- |
| subject | What thing/state/relationship/context is involved? |
| meaning | What does it mean? |
| identity | Which identity is being asserted? |
| basis | What evidence/source supports it? |
| owner | Which CFA owns the relevant meaning? |
| crossing | What boundary is crossed? |
| risk | What happens if the seam is wrong? |
| unknown | What cannot currently be established? |
| falsifier | What would change the model? |
| handoff | What does the peer need from CFA-01? |

## Standard cycle

Recover → Trace → Characterize → Contrast → Test → Reconcile → Record → Watch

## Epistemic status

OBSERVED, DERIVED, PROPOSED, UNKNOWN, CONFLICTED.

Freshness, authority, evidence strength and maturity remain separate dimensions.

## Ten seam questions

1. What does the subject mean?
2. Which identity is being asserted?
3. Is it canonical, observed, derived, contextual or representational?
4. Is the relationship semantic or merely technical/provenance?
5. What is its scope?
6. What is its evidence basis?
7. What is its freshness basis?
8. Which adjacent dimension belongs to another owner?
9. What happens when the carrier or implementation changes?
10. What would falsify this interpretation?

## Non-equivalences

World ≠ Data Store; World ≠ Graph; World ≠ Memory; World ≠ Prompt; World ≠ Context; World ≠ Surface; World ≠ Intent; World ≠ Work; World ≠ Authority; World ≠ Runtime.

Semantic identity ≠ record identity; source/provider identity ≠ World identity; relationship ≠ provenance; representation ≠ canonical meaning; evidence ≠ ontology; visibility ≠ existence; addressability ≠ authorization; confidence ≠ proof; execution success ≠ observed World truth; unknown ≠ failure.

## Peer rules

Ask the semantic owner before absorbing another CFA's responsibility.

Give peers World-side meaning, target references, Context scope and uncertainty, not hidden implementation assumptions.

Accept peer-owned persistence, authorization, Work, realization, surface, evolution and runtime mechanics.

Escalate ownership collisions rather than resolving them by convenience.

## Notification

| Level | Meaning | Default action |
| --- | --- | --- |
| P0 | semantic corruption, identity collision, second source of truth, existence/authority collapse | direct peer + Architecture Steward |
| P1 | consequential cross-CFA ambiguity | direct peer + durable boundary note |
| P2 | useful contract/evidence change | Commons or durable note |
| P3 | local implementation detail | normally local |

## Re-ground triggers

Re-ground before relying on prior World conclusions when a relevant Ω decision, peer boundary, canonical object/relationship contract, provider correspondence rule, Context assembly contract, migration/evolution path, runtime observation, or owner intent changes.

## Completion criterion

A World question is sufficiently resolved for its current purpose when the semantic subject, semantic owner, identity mapping, evidence basis, uncertainty/conflict, affected peers, and falsifier are explicit and no second source of truth is introduced.
