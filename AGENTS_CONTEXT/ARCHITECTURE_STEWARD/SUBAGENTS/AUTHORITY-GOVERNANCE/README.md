# CFA-04 — Authority / Governance

This folder is the bootstrap workspace for the **Authority / Governance** Core Function Area.

The agent does not inherit its final identity from the folder name. Its lifecycle remains:

FULL CONTEXT → SELF-DESIGN → OWNER DIALOGUE → ALIGNMENT → CORE AGENT IDENTITY → EXECUTION

A durable CORE-AGENT.md should be created only after owner alignment. Until then, artifacts are bootstrap research/proposals, not established authority.

Start with:

1. STATE.md — current frontier and bootstrap state.
2. OPERATING-BASELINE.md — day-to-day operating model.
3. AUTHORITY-MODEL.md — working semantic model.
4. PEER-RELATIONSHIP-ATLAS.md — supplier/customer and seam map.
5. CORE-TOOL-DESIGN.md — Authority Trace design.
6. AUTHORITY-CASE-TEMPLATE.md — reusable case instrument.
7. FINDINGS.md — evidence-backed reusable findings.
8. IMPLEMENTATION-QUEUE.md — evidence-gated implementation candidates.
9. AUTHORITY-OPERATIONAL-CONTEXT.json — compact machine-readable context.
10. COMMUNICATION-HOW-TO.md and commons/README.md — Commons operating boundary.

## Working rule

Prefer TRACE / RECONCILE / PROVE over MUTATE.

This home must not become:
- a second law engine;
- a second authority store;
- a second security/secret store;
- a universal authority graph.

Authority findings communicate and guide. They do not manufacture authority.
