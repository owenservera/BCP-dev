# Ω End-State Build Team — Access

> Status: FULL REPOSITORY / SHARED AGENT-SURFACE
> Date: 2026-09-28

## Access promise

The team gets the same practical repository and agent access available to the existing development path.

## Accessible information and machinery

- full BCP-dev source tree;
- Ω;
- destination/product vision;
- legacy VIVIM;
- BCP machinery;
- all existing Architecture Steward/CFA homes;
- Agent Commons;
- shared tests and tooling;
- branches and commits;
- research/documentation;
- external tools available in the connected development environment.

## Active team project home

The canonical durable project/control-plane home is `omega-endstate-build/`. Team-owned agent definitions, prompts, workstreams, roadmap, state, decisions, research, evidence, experiments, tools, product-specific material and integration records should prefer this location.

## Use of peer agents

The team may request help from existing agents or have those agents participate in this branch.

It is not required to preserve the current ten-CFA arrangement.

The team may conclude that:

- the existing roles are sufficient;
- the roles need a different grouping;
- some roles should become temporary specialists;
- new persistent roles are needed;
- a journey-oriented rather than domain-oriented organization is better.

The choice belongs to this team.

## Ownership boundaries

Access does not mean ownership of another agent's home.

Agents continue to own their durable identity/home surfaces.

This team owns its own:

- branch;
- context;
- roadmap;
- tasks;
- operating system;
- decisions;
- implementation lineage.

## Team-owned agent organization

The local Steward is explicitly authorized to create and progressively manage a new agent/subagent organization for this path. Existing agents may be reused as useful, but the current ten-CFA arrangement is not mandatory.

## Workspace safety

Each concurrently active agent must use its own isolated worktree or clone. Shared repository access does not permit shared autonomous checkouts.

## Security

Use the shared security and repository access controls.

The team may redesign architecture security as needed, but not by quietly bypassing it.

## Communication

The existing Commons system remains the communication substrate unless the team later establishes evidence that it needs a different mechanism.
