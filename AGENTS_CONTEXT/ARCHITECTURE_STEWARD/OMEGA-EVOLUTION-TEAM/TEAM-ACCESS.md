# Ω Evolution Team — Access Model

> Status: OWNER-DIRECTED
> Date: 2026-09-28

## Access principle

The Ω Evolution Team receives the **same repository and agent-system access surface** as the existing development team.

This is an access-sharing model, not a copy-and-fork of the agent infrastructure.

## Available directly

The team may inspect and use:

- the entire BCP-dev repository;
- current `main`;
- all accessible branches;
- all existing agent homes;
- Agent Commons;
- existing agent communication and handoff mechanisms;
- Ω runtime/code/tests/tooling;
- destination architecture and product research;
- BCP migration/forensic machinery;
- legacy VIVIM source/behavior mines;
- current CI/gates/build tooling;
- development-acceleration infrastructure;
- external research or tools available to the same connected GitHub account/session environment.

## Identity

Do not create a duplicate version of the existing agent identity registry just for this team.

Existing agents remain the agents.

A session participates in this team by binding to the team context and branch.

## Ownership

Access to all material does not grant permanent ownership of all material.

The team's specific ownership is:

- this team context;
- this branch;
- the team's roadmap/state/task queue;
- the Ω destination as evolved on this branch.

Other agent homes remain owned by their respective agents.

Shared implementation files should still have explicit temporary/current ownership when parallel work creates contention.

## Communication

Use the existing Agent Commons system.

Do not invent a separate team messaging substrate merely because this is a separate branch.

Team-specific coordination can be represented in this directory when it is durable strategic context rather than transient messaging.

## Security

Use the repository's existing access, identity, signing and security rules.

Do not weaken security merely to accelerate experimentation.

Security constraints can themselves be revisited as architecture questions, but any such change must be explicit and evidence-backed.
