# Open Frontier

> Current phase: research closure → factory implementation support. These questions are not a mandate for another broad research pass.

## Build-first priority

First resolve only the boundary questions that could force a change to the Ω factory while building the first composable product pieces.

- K0/K1 placement only where the first build exposes a real ambiguity.
- first-party/third-party symmetry in the pieces actually being built.
- composition replacement without core growth.
- active Work and Product Instance implications where the first executable compositions require them.
- zero-plugin/bootstrap only to the extent required by the shippable factory.

All other frontier questions remain valid research but should be deferred until they materially affect an active build decision.

1. Is every current Ω plugin genuinely consumable through the same boundary as an external plugin?
2. Which current contracts are protocol requirements versus historical artifacts?
3. Does canonical object storage require Core beyond the vault/plugin boundary?
4. Where should Work durability live?
5. Does authority enforcement require semantic policy in Core?
6. Can dependency/impact graphs support evolution generically?
7. Can system plugins be replaced without Product Instance discontinuity?
8. Which resource controls are constitutional enforcement versus plugin policy?
9. What happens to active Work when its implementation is replaced?
10. What minimum Core survives with zero first-party plugins?
11. Which apparent Core capabilities are implementation leakage?
12. Which historical Core labels were actually product/infrastructure?
13. Where does the plugin model end at the OS boundary?
14. Can Forge, healing, and ordinary installation share admission/evolution rules?
15. What is the exact K0/K1/trust-tier/constitutional-amendment relationship?

Do not close these for their own sake.
