# Product Environment Context — Compact Reference

## Destination intent

VIVIM is a sovereign personal computing environment. The machine boundary is part of the product, not an implementation afterthought.

## Existing destination dependency signals

High-risk unscoped frontiers include:

- native Windows shell;
- OS/filesystem/application integration;
- desktop interaction;
- product lifecycle;
- resource lifecycle;
- local security/secret integration;
- product diagnostics/recovery/repair.

## Existing product slice most affected

**VS1 — Run My VIVIM**

```
install → start → local durable world → reopen → same world
```

## Existing destination rule

Product Environment is delivery/machine boundary, not a replacement for Ω architecture.

## Core invariants

```
surface ≠ canonical storage
UI ≠ authority
OS handle ≠ canonical identity
capability ≠ realization
process memory ≠ durable truth
secret ≠ ordinary data
```

## Expected implementation direction

The eventual product should be assembled from governed capabilities over a durable world, with the native machine layer acting as a concrete realization boundary.
