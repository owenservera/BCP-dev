# Constitution — Rules Governing System Evolution

> Status: PROPOSED — destination working design, not ratified Ω law.

## Rule E-01 — Canonical truth is not mutable by representation

Changing a surface, cache, projection, parser, selector, or description must not silently redefine canonical meaning.

## Rule E-02 — History is preserved across meaningful evolution

A successful evolution does not erase the previous semantic state when that state is required to understand history, evidence, Work, or rollback.

## Rule E-03 — No silent semantic migration

A migration that changes meaning must declare the semantic delta.

Mechanical shape changes may use a simpler path only when equivalence is demonstrated.

## Rule E-04 — Evidence travels with change

A promoted change must be able to identify:

- what it replaced;
- why it changed;
- how it was tested;
- what evidence supported promotion;
- what authority approved it.

## Rule E-05 — Candidate is never authority

Generated, inferred, learned, healed, or AI-produced artifacts are candidates until they cross the required gates.

## Rule E-06 — Compatibility is multidimensional

Compatibility must not be reduced to API/schema compatibility.

At minimum evaluate where applicable:

- structural;
- semantic;
- identity;
- relationship;
- behavior;
- authority;
- evidence;
- persistence/recovery;
- projection;
- resource.

## Rule E-07 — Impact precedes consequential change

A consequential change must derive its known impact set before promotion:

```
subject
→ dependencies
→ dependents
→ active Work
→ policy/authority
→ projections
→ evidence
→ recovery
```

Unknown impact is a named state, not an empty impact set.

## Rule E-08 — Safe automation is bounded automation

Automatic maintenance is allowed only inside a declared safe envelope.

Outside that envelope the system must stop at proposal, refusal, or human gate.

## Rule E-09 — Rollback is a semantic operation

Rollback must identify the version/state being reactivated and preserve the evidence that the intervening version existed and was rejected/quarantined.

## Rule E-10 — No hidden privileged self-extension path

Forge-created, repaired, or third-party capabilities enter through the same capability/runtime/authority boundaries as ordinary capabilities.

## Rule E-11 — Constitutional change is exceptional

Changing these rules requires an explicit constitutional process.

Ordinary plugins, Personal Agent actions, model output, or provider healing may propose such a change but cannot self-ratify it.

## Rule E-12 — User ownership survives evolution

No evolution operation may silently transfer ownership, widen disclosure, or create an unreviewed durable external authority relationship.

## Rule E-13 — Unknown remains unknown

When correspondence, compatibility, causal impact, or historical continuity cannot be established, VIVIM records the uncertainty and chooses a governed fallback rather than inventing certainty.

## Rule E-14 — Evolution itself is observable

The running system should be able to answer:

- what changed;
- why;
- what is affected;
- what is now active;
- what evidence exists;
- what remains uncertain;
- how to reverse/reconstruct it.
