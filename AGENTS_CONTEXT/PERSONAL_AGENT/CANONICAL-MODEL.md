# Canonical Model

## Three layers
1. Canonical system reality: Product Instance, Composition, Plugin, Capability, Contract, Configuration, Object, Relationship, Revision, Work, Plan, Step, Attempt, Account, Session, Resource, Evidence, Law/Authority/Consent.
2. Self-Knowledge projections: system overview, capability/plugin pages, configuration, dependency/impact graphs, Work, history, explanations, language state and diagnostics.
3. Personal Agent: principal-facing intelligence that grounds questions/commands and uses normal Intent → Authority → Work semantics for changes.

## Reinforcing loop
Self-Knowledge → better grounding → better Intent → more precise Work → more evidence → richer Self-Knowledge

## Epistemic law
EVIDENCE ≠ REPRESENTATION ≠ DESCRIPTION ≠ AUTHORITY
confidence ≠ proof
candidate ≠ realization
LLM output ≠ authority
unknown ≠ failure

## Answer model
A trustworthy self-answer should be able to carry: claim + basis + freshness + authority + evidence + optional action.

## Relationships
Examples: plugin → contributes → capability; composition → activates → plugin; plugin → depends-on → contract/capability; Work → uses → capability; Work → produces → Object; Object → supported-by → Evidence; language entry → influences → interpretation.

The dependency graph must derive from canonical references, not become a hand-maintained diagram.
