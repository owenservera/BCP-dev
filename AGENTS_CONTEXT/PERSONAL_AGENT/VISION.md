# Self-Describing System Vision

## Product primitive
The user should be able to ask: what is this system, what can it do, how is it configured, what is happening now, what depends on what, why did it decide this, and what can I change?

## Internal-wiki model
Use a wiki-like UX over structured reality:
- pages = projections over canonical objects;
- links = canonical relationships;
- revisions = history;
- citations = evidence/provenance;
- capabilities = executable affordances;
- configuration = declared data;
- explanations = deterministic traces;
- changes = Intent / Plan / Work.

The wiki is a presentation metaphor. The substrate remains typed, addressable, revisioned and evidence-backed.

## Scope
Self-knowledge must eventually cover Product Instance, Composition, Plugins, capabilities/contracts, configuration, runtime state, Work, accounts/sessions/resources, dependencies and impact, history, authority/refusals, evidence, language, personalization, and the Personal Agent itself.

## Plugin-native growth
plugin installed → contributions discovered → canonical facts visible → projections update → language contributions available → Personal Agent can explain/use the new capability.

Normal plugins should not require a manual encyclopedia entry to become understandable.

## Recursive property
The agent should be able to explain itself: how it interpreted a question, which sources it used, which capabilities it invoked, what authority applied, and what evidence supports the answer.
