# Context Bundle Protocol

## Purpose

Context is an organizational resource.

The objective is not maximum context.

The objective is the smallest sufficient context that allows an independent, well-grounded audit.

## Bundle layers

### Layer 0 — Mission

- primary company mission;
- department role;
- current authority;
- current review layer.

### Layer 1 — Target

- exact task;
- exact proposal/change/claim under review;
- requester;
- expected outcome.

### Layer 2 — Current state

- current roadmap frontier;
- relevant repository state;
- current baseline;
- known blockers;
- recent decisions.

### Layer 3 — Evidence

- direct implementation evidence;
- test output;
- diffs/history;
- primary external research.

### Layer 4 — Counter-evidence

- known disagreements;
- alternative designs;
- failed experiments;
- stale or contradictory records.

### Layer 5 — Prior context

- prior related decisions;
- earlier vetoes;
- prior outcome reviews;
- relevant durable organizational memory.

Prior governor conclusions belong here as context, never as proof.

## Atomic evidence rule

Every consequential conclusion should be traceable to small, addressable evidence units where possible.

A large document may be cited, but the result should identify the specific observation that matters.

## Dynamic expansion

When evidence is insufficient, ask:

What is the smallest additional context that could resolve this uncertainty?

Then retrieve that context.

Do not expand context merely because it is available.

## Context contamination controls

When evaluating another agent's proposal:

1. capture objective facts first;
2. form preliminary hypotheses;
3. inspect advocacy/reasoning;
4. explicitly mark where the reasoning changed your view.

Empirical studies have found position bias, artifact sensitivity and sycophancy in LLM evaluation systems, so reviewer context should not be treated as neutral merely because it is extensive.
