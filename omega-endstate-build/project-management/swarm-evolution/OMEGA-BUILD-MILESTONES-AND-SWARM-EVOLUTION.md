# Ω Build Milestones + Swarm Evolution Path

> These are delivery/coordination artifacts over the existing Ω design. They do not replace the existing CFA roadmaps, product vision, runtime design, resident-team research, Commons contracts or Truth & Trust gates.

## Swarm evolution path

### S0 — Baseline made executable
Exercise the already-provided OpenCode/opencode-swarm substrate, resident-team model, Commons, workspace isolation, project-management state and evidence model.

**Proof:** a real bounded task executes, is recoverable and leaves durable evidence.

### S1 — Resident operation
Operationalize the established resident model: stable identity, bounded responsibility, durable state, context compilation, handoff, restart/replacement.

**Gate:** resident work does not depend on one live session.

### S2 — Governed delegation
Make resident → worker delegation real: delegation ambit, admission, isolated workspace allocation, bounded lifecycle and evidence return.

**Gate:** multiple bounded workers operate without shared-workspace corruption or authority confusion.

### S3 — Team execution
Use residents together on real Ω work with dependencies, safe parallelism, review, integration and evidence aggregation.

**Gate:** a meaningful Ω slice is delivered by the team.

### S4 — Persistent organization
Add the existing desired/actual state, presence, reconciliation, restart recovery, replacement and persistent queues needed for an organization that survives process death.

**Gate:** organization survives interruption.

### S5 — Swarm-driven product delivery
Run the complete product loop:

**requirement → decomposition → assignment → implementation → verification → integration → product evidence**

**Gate:** repeated real Ω delivery.

### S6 — Evidence-driven self-improvement
Use observed failures/bottlenecks to run bounded improvement experiments:

**baseline → experiment → evidence → decision → promotion/rollback**

Apply the existing agent-, interaction- and organization-level evolution model.

**Gate:** repeated improvements demonstrably improve useful delivery/reliability without degrading protected properties.

### S7 — Adaptive development organization
Allow governed changes in execution capacity based on workload and observed bottlenecks while preserving stable resident responsibilities.

**Gate:** capacity changes are recoverable and evidence-backed.

### S8 — Autonomous Ω development loop
Run sustained development cycles with humans retaining product and protected authority while the organization performs the operational coordination, execution, verification, recovery and controlled evolution.

**Gate:** sustained autonomous delivery with evidence and rollback.

## Real Ω product milestones

### M0 — Development foundation
Reproducible local Ω development: canonical project-management state, isolated agent execution, OpenCode/swarm substrate, Commons, durable state and verification.

**Proof:** a recovered/fresh agent can understand the workspace and execute bounded Ω work.

### M1 — Browser substrate
Establish the real local Chrome substrate.

**Proof:** a real browser session is controllable/observable through the intended substrate with evidence and recovery.

### M2 — ChatGPT Web vertical slice
First complete provider realization.

**Proof:** VIVIM conducts a real multi-turn ChatGPT Web conversation using the user's existing browser/account context and preserves required local evidence/Vault continuity.

### M3 — Provider triad
Extend the governed realization seam to ChatGPT Web, Claude Web and Gemini Web.

**Proof:** provider-specific realization works behind the common governed seam, including drift/error observation.

### M4 — Sovereign Command Loop
Make the core loop real:

**Universal Prompt → semantic interpretation/compilation → choice/routing → browser/provider realization → evidence/Vault**

**Proof:** a user can issue a meaningful natural-language task and inspect what actually happened.

### M5 — Continuity / Vault
Make durable personal continuity real.

**Proof:** the user can leave and return, continue work, and reconstruct relevant history/lineage without dependence on a live provider session.

### M6 — Wider digital-world capability
Extend into governed interaction with the broader digital world.

**Proof:** a meaningful external-world journey completes with the established authority, consent and evidence model.

### M7 — Coherent product surface
Turn the proven substrate into the usable Ω/VIVIM experience: Windows surface, command center, attention/notifications, diagnostics/repair and evidence/provenance presentation.

**Proof:** representative user journeys work without developer intervention.

### M8 — Beta
Package for real external use.

**Proof:** a clean environment can install/launch, complete defined journeys, recover from expected failures and preserve the product's sovereignty/data guarantees.

### M9 — Ω built by the evolving swarm
The swarm itself becomes part of the proof.

**Proof:** the evolving swarm takes an authorized Ω milestone, forms the required execution capacity, builds it, verifies it, integrates it, records evidence and performs a bounded self-improvement based on the run.

## Coupling rule

The swarm and product evolve together:

**build enough swarm → use it on the next Ω milestone → observe bottleneck/failure → improve swarm → use improved swarm on the next Ω milestone → repeat.**

Do not finish the entire swarm in isolation before building Ω, and do not optimize swarm metrics detached from product delivery.
