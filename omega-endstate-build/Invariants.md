# Invariants

These are properties the system must preserve even as implementation, organization and architecture evolve.

1. **User sovereignty:** personal data, context and durable work remain under the user's control.
2. **Mission precedence:** product progress toward the VIVIM beta outranks organizational self-improvement.
3. **Provenance:** consequential claims and changes retain traceable lineage.
4. **Authority is explicit:** capability or permission does not itself create organizational authority.
5. **Evidence beats prestige:** identity, seniority, model confidence or consensus never substitute for evidence.
6. **Key separations remain intact:** IDENTITY != AUTHORITY != OBSERVATION != EVIDENCE != INTERPRETATION != DECISION != EXECUTION != OUTCOME.
7. **Confidence != proof; agreement != correctness; documentation != implementation; candidate != realization; unknown != failure.**
8. **Execution isolation:** concurrent autonomous work uses isolated workspaces and owned branches.
9. **Completion != acceptance:** finished work must not become trusted merely because a process ended successfully.
10. **Current reality wins:** when documentation and runtime disagree, preserve the disagreement and investigate it.
11. **Independent verification:** consequential self-authored claims require an independent challenge where practical.
12. **Governance is scoped:** no role gains broader authority merely through persistence, usefulness or repetition.
13. **No silent self-expansion:** organizational or constitutional changes require attributable evidence and an explicit decision path.
14. **Recoverability:** important state, decisions, evidence and outcomes must survive process/session replacement.
15. **Evolution is reversible:** promoted changes retain lineage, evaluation context and a rollback/supersession path.
16. **The product remains the proving ground:** development-system changes earn permanence through demonstrated utility.
